How 134 raw findings became 103 unique issues, what was merged, dropped, and re-ranked.

Started from 69 raw findings across the four persona reports (16 first-time-teacher, 19 org side, 15 first-run, 19 mobile) and emitted 46 issues. 15 raw findings were merged into other issues rather than dropped: the seat-cap-after-composing-invite and the two quota-toast findings folded into flow-11; "two overlapping staff-isolation mechanisms" folded into flow-03 (same union semantics, same fix); "no cross-test ranking" folded into flow-21 with the question-bank claim as one marketing-vs-product issue; the Generate no-roster dead-end copy folded into flow-02 and flow-26; "rosters both named Students" folded into flow-26; the org-creation vocabulary divergence folded into flow-44; "duplicate section and exam names accepted silently" and "step 1 has no exam date field" folded into flow-09; the two DataTable mobile findings merged into flow-28; the two auth-page findings for Login and Register merged; and the desktop and mobile halves of the toggle-deformation, UUID-header, bulk-import and page-title findings merged into single issues.

8 raw findings were dropped outright. Three were design choices restated as bugs: the icon-only sidebar with hover flyout (a deliberate collapsed rail, and the touch case is already covered by flow-06), step 1 asking eight marking-policy questions before questions (a deliberate wizard ordering; only its concrete part, the missing exam date, survived into flow-09), and the org dashboard being a class grid rather than a stat strip (a feature request for a dashboard that was never claimed to exist). Two were speculation the auditor did not observe: the analytics table column widths and frozen-column complaint, which the auditor explicitly measured from layout because no graded results existed, and the /rosters/new 500, which came from typing a URL for a route that is not defined in App.jsx at all (only /rosters/:id exists, so "new" was parsed as an id). Two were pure taste with no user cost: the class-overview stat tiles being non-interactive divs, and the exams table lacking a creator column. One was a seeded-demo artifact: the "bulk" search hit that turned out to be a student literally named "Bulk Test 1".

Severity was corrected downward in seven places. Two auditors called the missing bulk student import a blocker; it is completable manually, so it is the top-ranked major (flow-05). "Question text is mandatory" was called a blocker; it is a real product gap but the teacher can complete the job by typing, so major (flow-16). The org-admin-unreachable-on-mobile and review-queue-unreachable-on-mobile blockers were re-ranked major since both surfaces work on desktop (flow-06, flow-07). Conversely one was corrected upward: the roll-number grid bug (flow-10) was reported as a frontend layout nit, but the defect is in backend/omr/views.py:250 and the scan pipeline actively cross-checks that grid, so an unfillable grid systematically flags clean sheets into review.

Every file path in every issue was opened and confirmed. Three auditor file attributions were wrong and are corrected here: the roll-grid bug is backend/omr/views.py, not GenerateSheets.jsx; the Google button lives in components/auth/GoogleButton.jsx, not inline in Login/Register; and TestList.jsx's handleDelete deletes subjects, not tests, which is why the "no delete action" claim in flow-09 holds despite a delete existing in that file.
